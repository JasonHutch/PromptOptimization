## What makes a phrase domain-specific
A phrase is DOMAIN-SPECIFIC if the application domain must keep detail about it, track it, or apply business rules to it, or if its meaning would change in a different domain. Words that would appear in almost any software description (system, application, user, information, data, facility, capability, message) are NOT domain-specific.

4. **Adjectives, enumerations**: state-describing adjectives and conditional attributes that govern business rules or domain states (e.g., valid, daily, cancelled, pending, accepted, rejected), and each item of a list of alternatives the business keeps (kinds or variants of an entity, ways something is done, life-cycle steps, specific values like "French", "beginner", "automatic", "manual"). ## Scope & Filtering Rules (Strict)
- **Exclude background narrative**: the business's history, success, costs, market conditions, motives for building the system, or past trends (e.g., "doubled", "last several years").
- **Exclude specific real-world instances** used only as illustrations (e.g., "National Trade Show Services", "NTSS", "Las Vegas Convention Center", "Apple Inc").
- **Exclude software/UI actions**: what the software itself displays, suggests, stores, processes, archives, selects, enters, shows, searches, updates, signs, voids, opens, settles, sends, pays, processes through.
- **Exclude generic verbs** even if they appear in a business context: support, provide, allow, suggest, need, want, wish, keep track, make, check, handle, satisfy, cover, use, branch out into, show up, honored, available for rental, repaired, taken from, returned to (unless the movement is the core domain action like "check out").
- **Exclude light verbs**: has, have, possess, is, are, be, been, being, get, take, give, make, do — possession is Rule 6, classification is Rule 9.
- **Exclude generic organizational nouns**: company, business, employer, organization, staff, person, customer, member, participant, observer — unless the description gives them domain-specific properties or rules beyond mere participation.
- **Exclude generic document/record nouns**: form, file, cabinet, record, list, details, account, invoice, contract, reservation form, file cabinet — unless the description specifies their domain-specific structure or lifecycle.
- **Exclude purely evaluative adjectives**: excellent, modern, convenient, great, important, additional, different, similar, several, whole, single, frequent, possible, national, international, professional, invited, selected, on site, predefined, large, medium, small — unless they define a distinct state, kind, or value used in a business rule.
- **Exclude gerunds/nouns derived from excluded verbs** (e.g., "inviting speakers", "registering participants", "advertisement activities", "running", "organizing", "promoting", "distributing", "setting up", "on site registration", "creation", "promotion") — these describe processes, not domain entities. The domain entities are the nouns (speakers, participants, activities).
- **Rule 1 vs Rule 4**: If a word is a noun denoting a domain entity (Rule 1), do not list it again as an adjective/enumeration (Rule 4). E.g., "book", "language tape", "automatic" (gear type), "manual" (gear type), "sedan" (body type), "hatchback" (body type) are Rule 1 (kinds/variants), not Rule 4.
- **Rule 2**: Only extract explicit "X of Y" phrases where both X and Y are domain entities/properties. Do not infer "X of Y" from possession (Rule 6) or classification (Rule 7/9).
- **Rule 3**: Output the base form of the verb (lemma) without object. Include particle/preposition (e.g., "check out", "pay by", "send to").
- **Rule 3 Verbs - Core Domain Actions**: A verb is a core domain action if it represents a primary business transaction or event (e.g., "rent", "reserve", "borrow", "issue", "check out", "pay", "return to", "taken from"). Exclude verbs describing system implementation (process, archive, store, update, scan, enter, search, sign, void, honor, send to, pay by, process through, track, open, settle).
- **Rule 3 Verbs - Passive Voice**: Include passive voice verbs only if the agent is a domain role (e.g., "is checked out by customer" -> "check out"). Exclude passives describing system behavior (e.g., "is processed", "is archived", "is scanned").
- **Rule 4 Enumerations/States**: Include adjectives/values ONLY if they represent distinct states/kinds used in rules (e.g., "pending", "accepted", "rejected", "automatic", "manual", "sedan", "hatchback", "large", "medium", "small", "invited", "selected", "daily", "valid"). Exclude descriptive adjectives (national, international, professional, predefined, on site, whole, entire).
- **Rule 1 vs Rule 4 (Kinds/Variants)**: Nouns representing distinct types/kinds of a parent entity (e.g., "language tape", "book" as types of "loan item"; "sedan", "hatchback" as types of "body type"; "automatic", "manual" as types of "gear change") are Rule 1. Do not list them under Rule 4.
- **Rule 6 Possession**: Extract only explicit "has/have/possess" statements. Do not extract for generic record nouns (account, invoice, contract, record, file, form, cabinet, list, details). E.g., exclude "account records service charge", "invoice covers rental".
- **Rule 7 Composition**: Extract only explicit structural phrases ("consists of", "made up of", "includes", "grouped into", "involves", "comprises"). Do not extract "involves" for process steps (e.g., exclude "organizing involves inviting"). Do not extract "includes" for state lists (e.g., exclude "proposal includes pending review").
- **Rule 9 Generalization**: Extract only explicit classification phrases ("is a", "is known as", "is a kind of", "types of", "can be regarded as", "including" used for classification). Do not extract for state values (e.g., exclude "booth size is a large", "proposal status is a accepted").
- **Rule 1 Entity Properties**: Include specific properties/attributes of domain entities when explicitly mentioned (e.g., "bar code reader", "book bar code", "current loan", "time of reservation", "period of time", "additional charge", "rental charge").
- **Rule 3 Verb Lemmatization**: Always output the base form (lemma) of the verb. E.g., "issued" -> "issue", "borrowed" -> "borrow", "reserved" -> "reserve", "scanned" -> "scan", "entered" -> "enter", "stamped" -> "stamp", "searched" -> "search", "identified" -> "identify", "processed" -> "process", "checked out" -> "check out", "prepares" -> "prepare", "creates" -> "create", "runs" -> "run", "invited" -> "invite", "reviewed" -> "review", "attended" -> "attend".
